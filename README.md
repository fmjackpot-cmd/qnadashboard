# 예상질의 회의 대시보드

PDF 자료를 업로드해 관리자와 참여자가 함께 열람하는 브라우저 대시보드입니다. 관리자가 문항을 선택하면 참여자 화면에 우선 표시되며, 참여자는 각자 자유롭게 탐색할 수 있습니다.

## 로컬 실행

`.env.example`을 참고해 로컬 `.env`에 `ABLY_API_KEY`와 6자 이상의 `MEETING_ADMIN_KEY`를 설정한 뒤 실행합니다. 실제 키는 Git에 올리지 않습니다.

```powershell
.\run-local.bat
```

`http://localhost:8888`을 일반 창과 시크릿 창에서 각각 엽니다. 일반 창에서는 **관리자로 시작하기**로 PDF를 업로드하고, 시크릿 창에서는 **회의 참여하기**로 같은 회의 코드를 입력합니다. 종료는 터미널에서 `Ctrl+C`입니다.

## 앱 창으로 실행하기

`run-app.bat`을 더블클릭하면 로컬 서버가 시작된 뒤 Edge(없으면 Chrome)의 앱 창으로 대시보드가 열립니다. 탭 표시줄·북마크·주소창 없이 사용하며, 창 크기 조절·최소화·Alt+Tab·Windows 화면 분할을 사용할 수 있습니다. 브라우저 설치 위치를 찾지 못하면 오류를 안내합니다.

실행 터미널은 열어 두세요. 앱 창을 닫아도 서버는 유지되며, 종료는 터미널에서 `Ctrl+C`입니다. 기존 `run-local.bat` 서버가 켜져 있다면 먼저 종료한 뒤 실행하세요. 로컬 주소는 이 PC에서만 접근할 수 있으므로 여러 PC에서 회의를 진행할 때는 배포 주소를 사용하세요.

배포 사이트는 Edge에서 해당 주소를 연 뒤 **… → 기타 도구 → 앱 → 이 사이트를 앱으로 설치**를 선택하면 시작 메뉴와 작업 표시줄에서 앱으로 실행할 수 있습니다. 브라우저 버전에 따라 앱 메뉴 위치가 다를 수 있습니다. [Microsoft 공식 안내](https://support.microsoft.com/en-us/edge/install-manage-or-uninstall-apps-in-microsoft-edge)

## 화면 표시

뷰어 상단의 **목록 숨기기 / 목록 보이기**로 왼쪽 질의번호 목록을 접고 펼칩니다. 휴대폰에서는 같은 버튼으로 목록 서랍을 엽니다. PDF 기본 확대값은 **140%**이며 문항 이동·창 크기 변경 시 수동 확대값을 유지합니다. **맞춤** 버튼을 누르면 화면 가로폭에 맞추며, 이후 `+` 또는 `−`를 누르면 다시 수동 확대가 적용됩니다.

## 검증

```powershell
.\run-tests.bat
```

자세한 검증 방법은 [tests/README.md](tests/README.md), 운영 배포 방법은 [Netlify_배포안내.md](Netlify_배포안내.md)를 참고하세요.

## 폴더 구성

| 경로 | 용도 |
| --- | --- |
| `index.html`, `app.js`, `live-session.js`, `style.css` | 화면·PDF 분석·회의 연결 |
| `netlify/` | 관리자 인증, Ably 전송, PDF 저장·조회 API |
| `scripts/` | 빌드와 로컬 실행 도구 |
| `tests/` | 자동 테스트와 검증에 필요한 PDF 2개 |
| `netlify-deploy/`, `netlify-deploy.zip` | 생성되는 배포 패키지, Git 제외 |
| `node_modules/` | 로컬 실행에 필요한 패키지, Git 제외 |
| `local-archive/` | 테스트에 사용하지 않는 PDF 원본의 로컬 보관, Git 제외 |

기본 PDF는 자동으로 열리지 않습니다. 관리자 업로드 한도는 50MB이며, 참여자는 회의 자료와 자료구분을 자동으로 받습니다. GitHub 푸시는 요청할 때만 진행합니다.

### 여러 관리자가 한 회의 제어하기

첫 관리자는 **관리자로 시작하기**에서 회의 코드·인증키·PDF를 입력합니다. 추가 관리자는 **같은 회의 코드와 관리자 인증키**를 입력하고 PDF를 선택하지 않은 채 **관리자로 연결**을 누르면 기존 회의 자료와 현재 문항을 받습니다. 참여자는 같은 회의 코드로 한 번만 접속하면 됩니다.

각 관리자가 문항을 선택하거나 **현재 화면 전송**을 누를 때마다 참여자 화면이 전환됩니다. 관리자들은 각자 자료를 탐색하며 번갈아 전송하고, 참여자는 나중에 처리된 전송을 따라갑니다. PDF를 새로 선택하면 회의 전체의 자료가 교체되므로 추가 접속 시에는 선택하지 마세요. 다른 관리자가 자료를 교체했으면 회의 설정에서 PDF 선택 없이 다시 연결해 새 자료를 받으세요.

## 카테고리별 예상질의 목차

왼쪽 구분 열에 부서·주제가 있고 카테고리마다 번호가 다시 시작하는 목차는 **카테고리순**에서 왼쪽 셀의 이름과 원래 문항 번호를 표시합니다. **번호순**에서는 전체 질의에 1부터 연속 번호를 부여합니다. 번호 버튼과 제목 목록 모두 같은 규칙을 사용하며, 같은 번호가 여러 카테고리에 있어도 각 문항으로 구분해 이동합니다.

이 표 양식은 외부 AI 없이 읽고, 목차 순서와 본문의 `【번호】` 또는 `[번호]`를 대조해 실제 시작 페이지를 연결합니다. 목차의 쪽수가 오래되었거나 비어 있어도 본문 번호가 모두 대응하면 연결할 수 있습니다. 목차와 본문의 번호·개수가 다르면 부분 결과를 표시하지 않고 오류를 안내합니다.

## 수감자료 프로토타입

**관리자로 시작하기** 팝업에서 자료구분 라디오 버튼(**예상질의·답변서 / 행정사무감사 수감자료**)을 선택하고 PDF를 업로드합니다. 기본값은 예상질의·답변서이며, 이미 열린 자료가 있으면 해당 자료구분이 선택됩니다. 참여자는 자료구분이나 파일을 따로 선택하지 않습니다.

4.5MB를 넘는 파일은 3MB 단위로 자동 전송합니다. 서버에서 전체 SHA-256을 검증하고 관리자가 같은 자료를 다운로드·분석한 뒤 회의 자료를 전환합니다. 참여자도 조각을 합친 뒤 SHA-256을 검사합니다. PDF 파일 자체를 분할하거나 압축하지 않습니다.

수감자료는 문서 전체에서 목차를 찾아 소관부서·요구자료 번호·제목·인쇄 쪽번호를 읽습니다. 중간에 나오는 개별자료 목차, 열 제목이 생략된 연속 목차, 복수 소관부서를 처리합니다. 외부 AI 호출은 사용하지 않습니다. 문서 분석 진행 쪽수를 표시하며, 큰 자료는 각 기기에서 처음 분석하는 데 시간이 걸립니다.

수감자료의 버튼에는 요구자료 번호 대신 **인쇄된 문서의 시작 쪽번호**가 표시되며, 기본 정렬은 **페이지순**입니다. **소관부서** 드롭다운에서 부서를 선택하면 해당 부서가 단독 또는 공동 소관인 항목과 **본청각과(본청 공통)** 항목이 중복 없이 함께 표시됩니다. 목차 상단의 ‘기관 공통’이라는 분류만으로 모든 항목을 포함하지는 않습니다. 예를 들어 행정과 선택 시 소관부서 칸에 행정과 또는 본청각과가 있는 항목이 나옵니다. **전체 부서**를 선택하면 전체 목록으로 돌아갑니다. 제목 목록에도 같은 필터가 적용되며, 이전·다음 이동은 필터된 페이지순을 따릅니다. 필터 선택은 각자 화면에만 적용되고, 관리자가 선택한 자료를 전송하는 기능은 그대로 동작합니다.

현재는 텍스트가 포함된 동일한 표 양식을 대상으로 하는 로컬 프로토타입입니다. Netlify 실환경의 저장·전송 시간과 실제 Ably 연결은 배포 후 별도로 확인해야 합니다. 업로드 중 실패한 임시 조각의 자동 정리는 아직 구현하지 않았습니다. 배포 패키지 zip은 정적 화면이며 서버 함수 변경은 기존 Git/Netlify 빌드 경로로 함께 배포해야 합니다.
