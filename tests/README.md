# 파서 검증

Windows PowerShell에서 `pnpm`을 찾지 못하면 프로젝트 폴더에서 아래 명령을 실행하세요. PATH의 Node.js 또는 이 PC에 있는 번들 Node.js를 사용하며, 전역 설치나 PATH 변경 없이 자동 테스트를 실행합니다.

```powershell
.\run-tests.bat
```

이 명령은 자동 테스트만 수행합니다. Netlify에 배포하거나 Git 커밋/푸시를 하지 않으며, 실제 Ably 네트워크 연결은 별도 확인이 필요합니다.

## 관리자·이용자 화면을 함께 테스트하기

프로젝트 폴더에서 다음 명령을 실행하면 Node.js를 자동으로 찾아 배포용 화면을 만들고 로컬 서버를 실행합니다. `pnpm`, Netlify CLI, Netlify 로그인/사이트 연결은 필요하지 않습니다.

```powershell
.\run-local.bat
```

1. 로컬 프로젝트의 `.env`에 `ABLY_API_KEY`와 6자 이상의 `MEETING_ADMIN_KEY`를 입력합니다. Netlify 계정에만 저장한 키는 이 로컬 실행 파일에서 자동으로 가져오지 않습니다. `.env.example`에는 실제 키를 넣지 마세요.
2. 실행 후 `http://localhost:8888`을 일반 창과 시크릿 창에서 각각 엽니다. 터미널은 실행 중인 상태로 둡니다.
3. 초기화면에서 자료구분을 선택하고 일반 창에서 **관리자로 시작하기**를 누른 뒤 회의 코드·관리자 키·50MB 이하 PDF를 선택해 **PDF 업로드 후 회의 시작**을 누릅니다. 시크릿 창은 **회의 참여하기**에서 같은 회의 코드만 입력해 같은 PDF와 현재 문항이 자동으로 열리는지 확인합니다. 자료를 열기 전에는 문항 목록·도구 모음이 숨겨지고, 참여자에게 관리자 입력 항목이 보이지 않아야 합니다.
4. 이용자의 자유 탐색 중 관리자 이동이 우선 반영되는지, 관리자가 **파일 열기**로 자료를 교체하면 이용자도 새 PDF를 여는지 확인합니다. 재전송과 이용자 새로고침 후 최신 PDF·문항 적용도 확인합니다.
5. 종료할 때 터미널에서 `Ctrl+C`를 누릅니다. 포트가 사용 중이라면 기존 테스트 서버를 먼저 종료하세요.

이 서버는 실제 관리자 인증·PDF 업로드·Ably 토큰 발급·발행 코드를 사용하며 실제 Ably 앱에 연결합니다. 채널은 실행할 때마다 생성하는 로컬 테스트 전용 이름을 사용합니다. 최신 문항과 PDF 저장은 메모리 대역이므로 종료하면 사라집니다. 실제 Netlify 런타임과 Blobs 저장소 검증은 배포 후 별도로 해야 합니다. 정적 파일은 `netlify-deploy`에서만 제공하며 `.env`와 서버 소스는 제공하지 않습니다. 키를 수정했으면 서버를 재시작하세요. 키가 누락돼도 화면은 열리며 터미널과 회의 연결 창에 필요한 설정이 표시됩니다.

- 전체 회귀 검증: `node --test tests/*.test.cjs`
- 관리자 우선 회의 검증: `node --test tests/meeting.test.cjs`
- Ably 실시간 전송 검증: `node --test tests/ably.test.cjs`
- 회의 PDF 업로드·자동 전환 검증: `node --test tests/meeting-documents.test.cjs tests/meeting-ui.test.cjs tests/local-server.test.cjs`
- 회의 테스트는 서버 핸들러와 복수 이용자 세션을 함께 실행해 자유 탐색, 관리자 우선 전환, 동일 문항 재전송, 재연결, 회의 격리 및 관리자 인증을 검사합니다. Ably 테스트는 반복 HTTP 요청 없음, 수신 전용 토큰, SDK 연결 종료·갱신·복구, 오래된 스냅샷 방지 및 문서 로딩 중 최신 이벤트 적용을 검사합니다. 실제 Ably 연결과 Netlify Blobs는 키 설정·배포 후 두 기기로 확인해야 합니다.

- 단위·회귀 테스트: `node --test tests/parser.test.cjs`
- 실제 PDF 통합 테스트: `node tests/pdf-integration.cjs <pdf.js-3.11.174의-pdf.cjs-절대경로> <pdf.worker.cjs-절대경로>`
- 통합 검증에 필요한 원본 PDF 2개는 `tests/fixtures/pdfs/`에 보관합니다. 그 외 참고 PDF는 로컬의 `local-archive/reference-pdfs/`로 옮겼으며 Git과 배포 패키지에는 포함하지 않습니다.
- PDF.js는 index.html과 같은 3.11.174 버전을 사용합니다. CDN의 pdf.min.js와 pdf.worker.min.js를 각각 .cjs 파일로 저장해 경로를 전달합니다.

2026-10-29 검증 결과: 회귀 테스트 5개 통과. 행정사무감사 PDF 120쪽의 47개 문항 시작·끝 쪽수 모두 목차와 일치. 공유재산관리계획 PDF 14쪽의 10개 문항 시작 쪽수 일치. API 키가 설정된 경우에도 두 표 형식은 외부 AI 호출 없이 분석됨.

브라우저 제어 연결이 없어 대시보드 화면 조작은 검증하지 못했습니다. 원본 PDF 목차는 이미지로 렌더링해 확인했습니다.

## 수감자료 및 대용량 전송 검증 (2026-11-04)

- 전체 자동 테스트에 25MB 파일의 분할 업로드·모드 전달·원본 복원, 누락/변조/만료/인증 실패, 참여자 분할 다운로드, 연속·중간 목차 검증을 포함합니다.
- 실제 수감자료 검증: `node tests/receipt-integration.cjs <pdf.cjs> <pdf.worker.cjs> <2026년-수감자료-PDF-절대경로>`
- 실제 PDF는 저장소에 복사하지 않습니다. PDF.js 3.11.174로 1,690쪽의 목차 22쪽·요구자료 145건을 읽고 각 시작 페이지의 인쇄 쪽번호 및 요구자료 번호를 검증합니다. 같은 파일을 로컬 HTTP 서버로 분할 업로드·다운로드하여 원본 바이트 일치와 참여자 자료구분 전달도 검사합니다. 실시간 브로커는 이 통합 테스트에서 대역을 사용합니다.
- 2026-11-04에는 브라우저/컴퓨터 제어 호스트가 연결되지 않아 실제 화면 클릭 검증은 수행하지 못했습니다. Netlify 배포도 수행하지 않았습니다.
